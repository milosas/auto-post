<task type="auto">
  <name>Task 2: Create usage limit query helpers</name>
  <files>lib/usage/queries.ts</files>
  <action>
    Create lib/usage/queries.ts with two main functions:

    **getUsage(userId: number, timezone: string)**: Get current usage status
    - Query usageLimits table by userId
    - If no record exists, create one with usedCount=0, resetAt=getNextMidnightUTC(timezone)
    - If current time >= resetAt, reset counter (set usedCount=0, update resetAt)
    - Return { used: number, limit: number, resetAt: Date }
    - Limit is hardcoded to 3 for free tier

    **checkAndIncrementUsage(userId: number, timezone: string)**: Atomically check and increment
    - First call getUsage to handle reset logic
    - If already at limit, return { allowed: false, used, limit, resetAt }
    - Use atomic SQL increment with WHERE constraint to prevent race conditions:
      ```typescript
      const [updated] = await db
        .update(usageLimits)
        .set({
          usedCount: sql`${usageLimits.usedCount} + 1`,
          updatedAt: now
        })
        .where(and(
          eq(usageLimits.id, usage.id),
          sql`${usageLimits.usedCount} < ${limit}` // Race condition protection
        ))
        .returning();
      ```
    - If update returns empty (race condition hit limit), return { allowed: false }
    - Return { allowed: true, used: updated.usedCount, limit, resetAt }

    Import from:
    - @/app/db (db instance)
    - @/app/db/schema (usageLimits, users tables)
    - drizzle-orm (eq, and, sql)
    - ./timezone (getNextMidnightUTC)
  </action>
  <verify>TypeScript compiles: npx tsc --noEmit lib/usage/queries.ts</verify>
  <done>
    - getUsage handles create, reset, and return current state
    - checkAndIncrementUsage uses atomic increment with constraint
    - Race conditions prevented by WHERE clause
  </done>
</task>

<task type="auto">
  <name>Task 3: Create usage API routes</name>
  <files>app/api/usage/route.ts</files>
  <action>
    Create app/api/usage/route.ts with GET and POST handlers:

    **Common setup:**
    - Use Node.js runtime (export const runtime = 'nodejs' - needed for Drizzle)
    - Import createClient from @/lib/supabase/server
    - Import db and tables from @/app/db and @/app/db/schema
    - Import query helpers from @/lib/usage/queries

    **GET /api/usage**:
    1. Authenticate: Get user from supabase.auth.getUser()
    2. If no auth user, return 401 { error: 'Unauthorized' }
    3. Look up internal user ID from users table by authId
    4. If user not found in DB, return 404 { error: 'User not found' }
    5. Get timezone from X-Timezone header or fallback to 'UTC'
    6. Call getUsage(userId, timezone)
    7. Return JSON { used, limit, resetAt: resetAt.toISOString() }

    **POST /api/usage**:
    1. Authenticate (same as GET)
    2. Look up internal user ID (same as GET)
    3. Get timezone from X-Timezone header or fallback to 'UTC'
    4. Call checkAndIncrementUsage(userId, timezone)
    5. If not allowed, return 429 { allowed: false, used, limit, resetAt }
    6. If allowed, return 200 { allowed: true, used, limit, resetAt }

    Error handling: Wrap in try/catch, log errors, return 500 on unexpected errors.
  </action>
