<task type="auto">
  <name>Task 1: Create Stripe webhook route with signature verification and idempotency</name>
  <files>app/api/stripe/webhooks/route.ts</files>
  <action>
Create POST handler for Stripe webhooks:

CRITICAL: This route must NOT have any body parsing middleware. Use `request.text()` to get raw body BEFORE verification.

1. Get raw body and signature:
   ```typescript
   const body = await request.text();
   const signature = request.headers.get('stripe-signature');
   if (!signature) {
     return NextResponse.json({ error: 'No signature' }, { status: 400 });
   }
   ```

2. Verify webhook signature:
   ```typescript
   let event: Stripe.Event;
   try {
     event = stripe.webhooks.constructEvent(body, signature, process.env.STRIPE_WEBHOOK_SECRET!);
   } catch (err) {
     console.error('Webhook signature verification failed:', err);
     return NextResponse.json({ error: 'Invalid signature' }, { status: 400 });
   }
   ```

3. Idempotency check (BEFORE processing):
   ```typescript
   const [existingEvent] = await db
     .select()
     .from(webhookEvents)
     .where(eq(webhookEvents.stripeEventId, event.id))
     .limit(1);

   if (existingEvent) {
     console.log(`Event ${event.id} already processed, skipping`);
     return NextResponse.json({ received: true }); // 2xx = success
   }
   ```

4. Route to appropriate handler based on event.type:
   - `checkout.session.completed` -> handleCheckoutComplete()
   - `customer.subscription.updated` -> handleSubscriptionUpdated()
   - `customer.subscription.deleted` -> handleSubscriptionDeleted()
   - `invoice.payment_failed` -> handleInvoicePaymentFailed()

5. Record event as processed AFTER successful handling:
   ```typescript
   await db.insert(webhookEvents).values({
     stripeEventId: event.id,
     eventType: event.type,
     processedAt: new Date(),
   });
   ```

6. Return 200 on success, 500 on processing error (triggers Stripe retry)

Error handling:
- Return 400 for signature failures (don't retry)
- Return 500 for processing errors (Stripe will retry)
- Always return 2xx quickly if already processed (idempotent)

<task type="auto">
  <name>Task 2: Create webhook event handlers for subscription and credit events</name>
  <files>lib/stripe/webhooks/handlers.ts</files>
  <action>
Create event-specific handler functions:

1. **handleCheckoutComplete(session: Stripe.Checkout.Session)**
   - Get userId from session.metadata
   - Check session.mode:
     - If 'subscription': create/update subscription record
     - If 'payment': check metadata.type === 'credit_purchase', increment credits

   For subscriptions:
   ```typescript
   await db.insert(subscriptions).values({
     userId,
     stripeCustomerId: session.customer as string,
     stripeSubscriptionId: session.subscription as string,
     stripePriceId: session.metadata?.priceId || '',
     status: 'active',
     credits: 0,
     currentPeriodStart: new Date(),
     currentPeriodEnd: new Date(Date.now() + 30 * 24 * 60 * 60 * 1000),
     cancelAtPeriodEnd: 0,
   }).onConflictDoUpdate({
     target: subscriptions.userId,
     set: {
       stripeCustomerId: session.customer as string,
       stripeSubscriptionId: session.subscription as string,
       stripePriceId: session.metadata?.priceId || '',
       status: 'active',
       updatedAt: new Date(),
     },
   });
   ```

   For credit purchases:
   ```typescript
   const creditsToAdd = parseInt(session.metadata?.credits || '0');
   await db.update(subscriptions)
     .set({
       credits: sql`${subscriptions.credits} + ${creditsToAdd}`,
       updatedAt: new Date(),
     })
     .where(eq(subscriptions.userId, userId));
   ```
   Note: If no subscription record exists, create one with status 'free'.

2. **handleSubscriptionUpdated(subscription: Stripe.Subscription)**
   - Update subscription record:
     - stripePriceId from subscription.items.data[0].price.id
     - status from subscription.status (map to our statuses)
     - currentPeriodStart and currentPeriodEnd from subscription
     - cancelAtPeriodEnd flag

   Status mapping:
   - 'active' -> 'active'
   - 'past_due' -> 'past_due'
   - 'canceled' -> 'canceled'
   - 'incomplete' -> 'past_due'

3. **handleSubscriptionDeleted(subscription: Stripe.Subscription)**
   - Update subscription status to 'canceled'
   - Clear stripeSubscriptionId

4. **handleInvoicePaymentFailed(invoice: Stripe.Invoice)**
   - Log the failure for monitoring
   - Update subscription status to 'past_due'
   - Stripe Smart Retries handles actual retry logic

All handlers should:
- Throw errors if userId not found (returns 500, triggers retry)
- Use upsert pattern (events may arrive out of order)
- Log actions for debugging
  </action>
